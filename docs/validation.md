# Validation of the two instances

The OpenRouter token-demand instance has its own page: [validation_openrouter.md](validation_openrouter.md).

Numeric claims are generated by `scripts/build_validation_docs.py` from the current evaluations. The framing is observed before → change → actual outcome, non-simulation prediction and simulation → alternative behavior.

## Trip.com

The prediction uses pretreatment employee covariates, prior performance ratings and sourced behavioral priors. Neither arm's post-policy outcomes nor the observed endline response rate calibrates the simulation. The paper reports **9.8% attrition in the Airfare and IT divisions during the preceding six months** ([source](https://www.nature.com/articles/s41586-024-07500-2)). This division-level aggregate appears in the Before section. The download omits individual pre-period departures and their denominator. Pre-policy satisfaction is unavailable. The office-only group was observed alongside the hybrid group after the change and is used to measure the policy impact.

Daily choices use random draws keyed to employee and decision time. Trace sampling and survey noise have separate streams. Expected quits are estimated by summing hazards while employees remain at risk; a stopped survival product would be biased. Ordinal performance transitions preserve the pretreatment grade distribution. Gender is excluded from behavior, imputation and synthetic assignments.

| Outcome | Simulation | Actual | Absolute error |
|---|---:|---:|---:|
| Change in six-month attrition (hybrid minus office-only) | -2.3865 | -2.3971 | 0.0106 |
| Change in work satisfaction (0–10 points) | 0.3685 | 0.3507 | 0.0178 |
| Change in attrition, non-managers | -2.8467 | -3.2567 | 0.4100 |
| Change in attrition, managers | -1.0533 | 0.1693 | 1.2226 |
| Change in performance grade (1–5 points) | 0.0223 | -0.0556 | 0.0779 |
| Share of offered home days used | 0.5538 | 0.5232 | 0.0306 |
| Six-month attrition, office-only group | 8.6403 | 7.1951 | 1.4452 |
| Six-month attrition, offered hybrid work | 6.2538 | 4.7980 | 1.4558 |

Point predictions are ensemble expectations over 50 seeds. Predictive intervals use realized outcomes. Absolute attrition levels remain sensitive to the external turnover prior. Manager effects remain uncertain.

Other predictions use historical information only. No change carries forward 9.8% attrition and assumes zero policy impact. The simple two-day calculation scales the earlier four-day study's approximately 50% retention benefit: 9.8% × (1 − 50% × 2/4) = 7.35% attrition, or -2.45 percentage points of policy impact ([earlier study](https://doi.org/10.1093/qje/qju032)). Proportional scaling across schedules, jobs and periods is an explicit assumption. This second method is used only for overall attrition. The simulation's behavioral parameters and saved predictions are unchanged; the newly documented historical aggregate supplies context and comparison calculations, not a refit of the turnover prior.

This is a retrospective evaluation. The inherited prior revision log records earlier comparison and selection against experiment outcomes, so neither CI inclusion nor the close headline estimate establishes untouched prospective accuracy.

**Alternative: hybrid for everyone.** The same 20 seeds in both scenarios give expected company-wide attrition of 7.55% under the experiment arrangement and 6.10% under universal eligibility. This is a simulated alternative, not an observed causal estimate.

## Procurement purchase-to-pay

The process specification is selected using a January–June fit and July–August validation windows, then refitted through August 31. `calibration/fit.yaml` records the boundaries. The model's joint cumulative-incidence curves retain censored waiting cases, condition on previous activity and match state, and apply the payment calendar to cause-specific hazards. Roles are inferred from events before the prediction cutoff.

Before-policy windows are observed only and end before September 1. After-policy predictions continue each case from its observed prefix for fourteen days. Actual arrivals are supplied as exogenous inputs; all subsequent events are hidden. This is conditional continuation, not an August-only prediction of every later arrival or organizational change. All business metrics use the same eligible cases and horizon on both sides.

|---|---:|---:|---:|
| Cases completed within 14 days (%) | 6.801 | 13.144 | 11.793 |
| Median cycle time of completed cases (h) | 1526.146 | 1843.329 | 1715.755 |
| Cases with at least one exception (%) | 4.905 | 5.951 | 4.555 |
| Hand-offs per active case | 0.359 | 0.462 | 0.437 |
| Events per week in the horizon | 22927.750 | 29083.750 | 23659.167 |

| Outcome | Simulation MAE | Best non-simulation MAE | Error reduction |
|---|---:|---:|---:|
| Cases completed within 14 days (pp) | 1.351 | 2.467 (training average) | 45.3% |
| Median cycle time of completed cases (h) | 127.574 | 235.270 (training average) | 45.8% |
| Cases with at least one exception (pp) | 1.456 | 1.308 (carry forward) | -11.3% |
| Hand-offs per active case | 0.025 | 0.092 (training average) | 73.3% |
| Events per week in the horizon | 5424.583 | 1866.050 (training average) | -190.7% |

MAE is computed separately for each prediction window and then averaged, avoiding cancellation of opposite errors. Comparators are the observed pre-policy period carried forward, the pre-policy historical average, and carry-forward scaled by staffing. The best comparator is selected separately for each outcome. Negative error reduction means the simulation loses.

Next-activity accuracy is 81.48% versus 78.44% for the best prefix Markov model trained on the same data. This diagnostic is secondary to business-outcome accuracy.

**Alternative: no workforce expansion.** Matching cutoffs and seeds give completion of 11.79% under observed staffing and 11.78% under the alternative. The staffing intervention is simulated. Concurrent changes in order mix prevent interpreting the observed period difference as a staffing-only causal effect.

## Reproduction

Install dependencies and download the pinned inputs first; see [setup](setup.md). These commands normalize the data, regenerate both evaluations and reports, and verify the results.

```bash
uv run orgsim demo
uv run --extra dev pytest -q
uv run python scripts/check_bpi19_results.py
```

To reproduce model-selection validation after normalization, first run `uv run python instances/bpi19/ingest/run.py --training-end 2018-07-01`, then `uv run python instances/bpi19/ingest/audit/validate_cutoffs.py`; restore the final pre-policy fit with `uv run orgsim ingest bpi19` afterward. The validation harness rejects overlapping calibration or any validation window extending beyond the change date.

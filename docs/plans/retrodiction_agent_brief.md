# Brief for each retrodiction study team

You are a senior data scientist adding scored retrodictions to the WORKCAST platform (this repository; read `CLAUDE.md`, `docs/architecture.md`, `docs/contracts.md` and `docs/validation_openrouter.md` first; `instances/bpi19`, `instances/trip` and `instances/openrouter` are the three worked examples). The goal is the best accuracy that survives scrutiny: a client's analyst or an investor's technical reviewer must be able to rerun it and get the same numbers.

## What to deliver per case

An instance under `instances/<id>/` following `instances/_template` and the rules in `CLAUDE.md`:

- **Data:**
  - an ingest that downloads the public data (to the iMac SSD, see Compute);
  - `manifests/sources.json` with the SHA-256 of every raw file;
  - normalised tables under `data/normalized/`, git-ignored.
- **Before and after:**
  - an observed before period, an identifiable change, and a scored after period;
  - or rolling-origin cutoffs when the "change" is each new period.
- **Calibration** on data strictly before each cutoff.
- **Comparators, fixed before scoring:** carry-forward, historical average or seasonal naive, a trend, and the field's standard statistical method where one exists (for example ETS or ARIMA for series, a Markov prefix model for process logs). Report against all of them, and name the best.
- **`evaluation.json`** written by the world's `evaluate`, plus `results_view`, so the case shows in the UI.
- **A validation doc** `docs/validation_<id>.md`, generated by a script from `evaluation.json` and never typed by hand. The OpenRouter builder `scripts/build_openrouter_validation.py` is the pattern.
- **`runs/<id>/value_inputs.json`** with the headline figures the value case will cite. Each figure carries its exact path inside `evaluation.json`:
  - each comparator's error and the simulation's error on the headline outcome;
  - the outcome's mean actual level, so accuracy = 1 - error/level can be computed;
  - the number of predictions and the date span;
  - any operational quantity (cases per week, staff, trips, dollars) needed to put a dollar value on the improvement.
- **Tests in `tests/test_<id>.py`:**
  - a **leak test**: deleting all data after a cutoff leaves the prediction unchanged;
  - a test that every protocol cutoff is scored.

## Protocol (this is what makes the numbers defensible)

1. **Dev and held-out split.** The first quarter of the cutoffs (at least two) is for development. Make every modelling choice there: features, specification grid, priors, horizons. The remaining cutoffs are held out.
2. **Freeze before the held-out run.** Before running the held-out cutoffs, write `docs/plans/<id>_protocol.md` and commit it. It states the frozen design, the comparators, the headline metric and your predicted result. Then run the held-out cutoffs once.
3. **Report as measured.** If the held-out result is worse than predicted, report that. You may fix a bug found afterwards: record it in the protocol doc with the before and after numbers, and do not tune further.
4. **Headline metric.** Use a business outcome a manager reads, such as error in weekly completed cases, cycle time, separations, demand or adoption share. State it as both "error reduction versus the best classical comparator" and "accuracy = 100 x (1 - error / mean actual)".
5. **Retrospective.** If the design was chosen with outcomes visible, say so in the validation doc, as the OpenRouter doc does.

## Engineering rules

- **Reuse first.** Use the `process` world for event logs, the `workforce` world for employee-level data, and the `market` world's calibration code (rolling backtests, one-standard-error rule, damped trends, ranges) for aggregate series.
- **New world types.** Only add one when nothing fits, and register it in `orgsim/worlds/__init__.py`. Platform code never contains instance logic.
- **Python 3.12, `uv`, the repo's existing idiom.** No ad-hoc analysis: every figure comes from a committed script.
- **Commit to your own branch in your worktree.** Do not push and do not open a PR. The lead merges.
